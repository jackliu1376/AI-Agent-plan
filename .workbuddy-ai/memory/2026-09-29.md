## 真实 DeepSeek 实跑（用户报 404 后排查）

### 用户报错：`openai.NotFoundError: Error code: 404`

- **根因**：`.env` 里 `DEEPSEEK_BASE_URL=https://api.deepseek.com/anthropic`。
  DeepSeek 有两套兼容端点，`/anthropic` 是给 Claude Code 用的 Anthropic 兼容端点，
  不是 OpenAI 兼容端点。openai SDK 会拼 `/chat/completions` → 404。
- **正解**：`DEEPSEEK_BASE_URL=https://api.deepseek.com`（不要带 `/anthropic`，也不要带 `/v1` 之外的多余路径）。
- **加固**：`agent/config.py` 新增 `Settings.validate()` + `KNOWN_BAD_BASE_URL_SUFFIXES`
  黑名单（`/anthropic`、`/beta`、完整请求路径），`DeepSeekClient.__init__` 构造时即校验并报人话错误。

### 🔴 安全问题：真实 API Key 出现在 `.env.example`

### 模型不知道"今天"导致反问日期

- 现象：用户说"周末去成都"，Agent 反问"具体是哪个周末"。
- 根因：系统提示词无时间锚点，LLM 不掌握当前日期。
- 修复：`render_system_prompt()` 注入 `{{CURRENT_DATE}}` / `{{CURRENT_WEEKDAY}}`；
  system.md 增「当前时间」章节 + 相对时间推算规则；澄清门控改为白名单式（明确"不需要问"的情形）。
- 验证：修复后自行推出 2026-10-03(周六)~10-04(周日)，直接调天气，不再提问。

## 国际城市支持（用户反馈"纽约天气和景点都查不到"）

### 🔴 缺陷 7：天气工具静默返回错误城市（比报错更严重）

探测 Open-Meteo 地理编码的真实行为：

| 查询 | 返回 |
|---|---|
| `name=纽约` | 无结果 |
| `name=东京` `language=zh` | **江苏·东京 (32.21, 119.29)** ← 中国江苏的一个镇 |
| `name=New York` | **内布拉斯加州·约克** |
| `name=巴黎` | 正确 |

即：问东京天气会**不报错地把江苏天气当东京返回**，直接违反"不臆造"约束。

**修复**：新增 `mcp_server/data/cities.py`（55 个城市的本地坐标表，含中文名/英文名/别名/
坐标/国家/时区），天气与交通共用。`resolve_city()` 改为本地表优先；未命中才回落 API，
且拉 10 个候选按「行政级别 PPLC>PPLA>PPL + 人口」排序，返回
`resolved.{name,country,admin1,matched_via,confidence}`，低置信度附 ⚠️ 警告。

### 🔴 缺陷 8：景点库只有 5 个中国城市
