## 真实 DeepSeek 实跑（用户报 404 后排查）

### 用户报错：`openai.NotFoundError: Error code: 404`

- **根因**：`.env` 里 `DEEPSEEK_BASE_URL=https://api.deepseek.com/anthropic`。
  DeepSeek 有两套兼容端点，`/anthropic` 是给 Claude Code 用的 Anthropic 兼容端点，
  不是 OpenAI 兼容端点。openai SDK 会拼 `/chat/completions` → 404。
- **正解**：`DEEPSEEK_BASE_URL=https://api.deepseek.com`（不要带 `/anthropic`，也不要带 `/v1` 之外的多余路径）。
- **加固**：`agent/config.py` 新增 `Settings.validate()` + `KNOWN_BAD_BASE_URL_SUFFIXES`
  黑名单（`/anthropic`、`/beta`、完整请求路径），`DeepSeekClient.__init__` 构造时即校验并报人话错误。

### 🔴 安全问题：真实 API Key 出现在 `.env.example`

## 第三轮：彻底解决"查不到城市"（用户反馈）

### 量化问题

对 40 个本地表未收录城市实测：**仅 24 个可用（60%），8 个返回错误地点，8 个无结果**。
错误地点的例子：`开罗`→美国伊利诺伊州、`里斯本`→美国北达科他州、`米兰`→美国、
`马尼拉`→美国、`日内瓦`→机场、`开普敦`→机场。

### 解法：三层城市解析

1. **策展表** `cities.py`（170 条，人工维护）—— 常用目的地 + **非城市目的地**
   （圣托里尼、长滩岛、少女峰、马丘比丘、佩特拉、塞伦盖蒂…）+ 译名差异（科伦坡）。
2. **生成索引** `city_index.tsv`（**14,359 个中文城市名 / 229 个国家**）——
   新增构建脚本 `build_city_index.py`，从 GeoNames `cities15000.zip`（3.3MB）生成。
3. **Open-Meteo 地理编码** —— 最后兜底，带 `confidence` 标记。

### 构建索引时踩的三个坑

- **繁简转换**：GeoNames 里不少城市只有繁体名（`維也納`/`米蘭`/`利馬`/`基輔`/`開普敦`/
  `加德滿都`/`瓦拉納西`），必须用 `zhconv` 转简体。连 `伊斯坦堡`→`伊斯坦布尔` 都能转。
- **行政区后缀归一化**：索引里是 `达沃市` 而用户输入 `达沃`；索引里是 `科威特市`
  而用户输入 `科威特城`。做法：给索引键额外注册「去后缀」变体 + 查询也去后缀。
  **剥离后短于 2 字的丢弃**，否则 `盐城`→`盐`、`聊城`→`聊` 会制造垃圾键。
- **国家代码→中文**：GeoNames 只给 `EG`，新增 `countries.py`（229 条）。
  **HK/MO/TW 一律标注为中国的一部分**，有专门测试守住。

### 查找顺序（重要，测试暴露的体验问题）

策展表精确 → **策展表去后缀** → 索引精确 → 索引去后缀 → 繁简转换后重跑。
「策展表去后缀」必须排在「索引精确」之前，否则输入 `上海市` 会返回索引里不够规范的
`上海市`，而不是策展表里人工校对的 `上海`。

### 结果

40 个失败样本全部修复。抽样 20 城实跑真实天气，数据均合理
（雷克雅未克 6.7~9.4℃、马尼拉 25.8~32.0℃、特罗姆瑟 6.8~10.0℃）。
测试 **188 passed**（test_cities 从 23 扩到 111，含 21 个参数化的错误解析回归用例）。

真实 Agent 验证：伊斯坦布尔（景点库不覆盖）→ 天气正常，景点如实报"⚠️ 数据缺失"
并列出覆盖的 12 城，**没有编造**，计划仍正常产出、依赖图无环。
